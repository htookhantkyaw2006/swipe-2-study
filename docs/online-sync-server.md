# Online Learning Sync Server Foundation

29 October 2026. Prepared on branch `feat/online-sync-server`.

This document specifies the server contract, schema migrations, concurrency architecture, RPC specifications, idempotency semantics, and recovery behavior for repeat-safe online synchronization of learning records.

---

## 1. Overview & Scope Boundaries

The **Online Learning Sync Server Foundation** establishes the authenticated backend contract for continuous, repeat-safe synchronization of learning data between client local storage and PostgreSQL/Supabase.

### In Scope
- Additive database migration (`supabase/migrations/20261029000300_online_sync_foundation.sql`).
- Authenticated batch mutation RPC (`public.s2s_apply_mutations`).
- Atomic learning reset RPC (`public.s2s_reset_learning`).
- Deletion tombstone tracking table (`public.user_item_tombstones`) with RLS.
- Idempotency receipt tracking tables (`private.sync_mutation_receipts`, `private.learning_reset_receipts`).
- Additive extensions to `public.s2s_account_snapshot` (exposing `tombstones`) and `public.s2s_import_guest` (tombstone check preventing resurrection).
- Comprehensive automated verification suite (`tests/onlineSyncServer.test.js`).

### Out of Scope (Scheduled for Subsequent Batches)
- Client-side background sync orchestrator and offline mutation queue.
- Frontend sync indicator UI or settings triggers.
- Learning progress/streak aggregates client reconciliation.
- User preferences cloud synchronization.
- Hosted migration deployment or production push.

## 2. Database Schema Extensions

### 2.1. Tombstones Table (`public.user_item_tombstones`)
Records explicit deletions of learning items so that stale offline clients or repeated guest imports cannot resurrect deleted records.

```sql
create table if not exists public.user_item_tombstones (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  item_key text not null,
  language text not null check (language in ('zh', 'ja')),
  kind text not null check (kind in (
    'saved_words', 'review_cards', 'learned_radicals', 'learned_kana', 'learned_sounds'
  )),
  written_form text not null,
  reading text not null default '',
  deleted_at timestamptz not null default now(),
  revision bigint not null check (revision >= 1),
  reset_version bigint not null check (reset_version >= 0),
  constraint uq_user_item_tombstones unique (user_id, item_key)
);
```

- **Row Level Security**: Enabled. Users can only read (`SELECT`) their own tombstones. Modifying tombstones is restricted to `service_role` and security definer RPC functions.
- **Index**: `idx_user_item_tombstones_owner_key` on `(user_id, item_key)`.

### 2.2. Mutation Receipts Table (`private.sync_mutation_receipts`)
Ensures repeat-safe idempotency for mutation batches.

```sql
create table if not exists private.sync_mutation_receipts (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  request_id uuid not null,
  input_hash text not null,
  reset_version bigint not null,
  result jsonb not null,
  created_at timestamptz not null default now(),
  constraint uq_sync_mutation_receipts unique (user_id, request_id)
);
```

### 2.3. Reset Receipts Table (`private.learning_reset_receipts`)
Tracks completed atomic learning resets, ensuring network retries of the reset command replay cleanly without double-incrementing generations or failing on reset version mismatches.

```sql
create table if not exists private.learning_reset_receipts (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  request_id uuid not null,
  previous_reset_version bigint not null,
  new_reset_version bigint not null,
  created_at timestamptz not null default now(),
  constraint uq_learning_reset_receipts unique (user_id, request_id)
);
```

## 3. Batch Mutation RPC Contract (`s2s_apply_mutations`)

### 3.1. Function Signature
```sql
public.s2s_apply_mutations(
  p_expected_user_id uuid,
  p_request_id uuid,
  p_expected_reset_version bigint,
  p_mutations jsonb,
  p_atomic boolean default false
) returns jsonb
```

### 3.2. Parameters
| Parameter | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `p_expected_user_id` | `uuid` | Yes | Initiating user ID; must match authenticated `auth.uid()`. |
| `p_request_id` | `uuid` | Yes | Unique idempotency token generated by the client. |
| `p_expected_reset_version` | `bigint` | Yes | Client's expected generation (`account_state.reset_version`). |
| `p_mutations` | `jsonb` (array) | Yes | Array of mutation objects (max 500 items, max 1MB). |
| `p_atomic` | `boolean` | No | Default `false`. If `true`, any revision conflict halts and rolls back the entire batch. |

### 3.3. Mutation Item Schema
Each element in `p_mutations` must be a JSON object:

```json
{
  "op": "upsert" | "delete",
  "language": "zh" | "ja",
  "kind": "saved_words" | "review_cards" | "learned_radicals" | "learned_kana" | "learned_sounds",
  "written_form": "你好",
  "reading": "nǐ hǎo",
  "client_id": "client-uuid-or-id",
  "base_revision": 1,
  "observed_at": "2026-10-29T12:00:00Z",
  "data": { ... }
}
```

- `op`: Either `'upsert'` (create or update) or `'delete'`.
- `client_id` (optional): Client tracking ID (string, max 128 chars), returned in the acknowledgement.
- `base_revision` (optional): Base revision the client based its mutation on (integer >= 0).
- `data`: Required for `'upsert'`, prohibited from carrying reserved column names (`id`, `user_id`, `item_key`, `revision`, `reset_version`, `created_at`, `updated_at`, `language`). Validates length and schema according to the established `user_items` standard.

### 3.4. Successful Return Shape
```json
{
  "status": "committed",
  "user_id": "11111111-1111-4111-8111-111111111111",
  "request_id": "99999999-9999-4999-8999-999999999999",
  "reset_version": "0",
  "applied_count": 2,
  "deleted_count": 1,
  "conflict_count": 0,
  "replayed": false,
  "acknowledged": [
    {
      "client_id": "c-1",
      "item_key": "a1b2c3...64hex",
      "language": "zh",
      "kind": "saved_words",
      "status": "applied",
      "revision": "2"
    },
    {
      "client_id": "c-2",
      "item_key": "d4e5f6...64hex",
      "language": "zh",
      "kind": "saved_words",
      "status": "deleted",
      "revision": "3"
    }
  ]
}
```

### 3.5. Conflict Handling
When `p_atomic = false` (default mode), stale mutations return an item-level conflict in the `acknowledged` array rather than aborting the entire batch:
```json
{
  "client_id": "c-3",
  "item_key": "e7f8a9...64hex",
  "language": "zh",
  "kind": "saved_words",
  "status": "conflict",
  "error": "STALE_REVISION",
  "server_revision": "5"
}
```
If the item was deleted on the server, `error` is `'RECORD_DELETED'`.
When `p_atomic = true`, encountering a stale revision immediately raises `REVISION_CONFLICT (40001)` and rolls back the entire batch.

### 3.6. Error Exceptions
| Exception Name | SQLSTATE | Cause |
| :--- | :--- | :--- |
| `ACCOUNT_REQUIRED` | `42501` | Missing or unauthenticated caller (`auth.uid() is null`). |
| `ACCOUNT_CHANGED` | `42501` | `p_expected_user_id` does not match `auth.uid()`. |
| `ACCOUNT_UNAVAILABLE` | `42501` | Account row missing or marked `deleting = true`. |
| `RESET_VERSION_CHANGED` | `40001` | `p_expected_reset_version` does not match `account_state.reset_version`. |
| `INVALID_MUTATION_REQUEST` | `22023` | Malformed parameters, missing request ID, or non-array mutations. |
| `MUTATION_LIMIT_EXCEEDED` | `22023` | Array length > 500 or payload text > 1 MB. |
| `MUTATION_REQUEST_REUSED` | `22023` | Request ID reused with a different mutation payload or reset version. |
| `INVALID_MUTATION_ITEM` | `22023` | Invalid `op`, `language`, `kind`, empty `written_form`, or reserved data keys. |
| `INVALID_MUTATION_REVISION` | `22023` | `base_revision` is negative or non-integer. |
| `INVALID_MUTATION_TIMESTAMP` | `22023` | `observed_at` cannot be parsed as a finite ISO timestamp. |
| `INVALID_MUTATION_DETAILS` | `22023` | String fields in `data` exceed length or type limits. |
| `INVALID_MUTATION_EXAMPLES` | `22023` | `examples` array exceeds 3 items or invalid structure. |
| `INVALID_MUTATION_COUNTERS` | `22023` | Counter fields (`seen`, `correct`, `wrong`, `streak`) fail mathematical integrity. |
| `ITEM_KEY_MISMATCH` | `22023` | Client-provided `item_key` does not match the canonical SHA-256 hash. |
| `REVISION_CONFLICT` | `40001` | Stale revision encountered when `p_atomic = true`. |

## 4. Atomic Learning Reset RPC Contract (`s2s_reset_learning`)

### 4.1. Function Signature
```sql
public.s2s_reset_learning(
  p_expected_user_id uuid,
  p_request_id uuid,
  p_expected_reset_version bigint
) returns jsonb
```

### 4.2. What Is Reset (Wiped)
An atomic learning reset resets the user's study records while preserving their identity and profile:
1. **`public.user_items`**: All active learning items for the user are deleted.
2. **`public.user_item_tombstones`**: All deletion tombstones for the user are cleared.
3. **`private.guest_import_receipts`**: All guest import receipts for the user are cleared.
4. **`private.sync_mutation_receipts`**: All mutation idempotency receipts for the user are cleared.
5. **Generation Increment**: `private.account_state.reset_version` is atomically incremented: `reset_version = reset_version + 1`.

### 4.3. What Is Preserved
The following tables and data are strictly **preserved**:
- **`auth.users`**: Account authentication identity and credentials.
- **`public.profiles`**: Display name, nickname, avatar URL, created_at, updated_at.
- **`public.user_preferences`**: Settings, display preferences, themes.
- **Storage Avatars**: Files under `avatars/${userId}/*`.
- **`private.account_deletion_attempts`**: Security rate-limiting counters and attempt history.

### 4.4. Successful Return Shape
```json
{
  "status": "reset",
  "user_id": "11111111-1111-4111-8111-111111111111",
  "request_id": "88888888-8888-4888-8888-888888888888",
  "previous_reset_version": "0",
  "reset_version": "1",
  "items_reset": true,
  "replayed": false
}
```

### 4.5. Repeat-Safe Idempotency
- When `s2s_reset_learning` is called with a reused `p_request_id` that was already completed for the owner:
  - If the receipt is found in `private.learning_reset_receipts`, it returns the cached result with `"replayed": true`.
  - It does **not** double-increment `reset_version`.
- When an in-flight mutation or import request carrying a pre-reset generation (`version 0`) arrives after a reset has bumped the generation to `1`:
  - It is immediately rejected with `RESET_VERSION_CHANGED (40001)`.

## 5. Additive Updates to Snapshot and Guest Import

### 5.1. `public.s2s_account_snapshot`
The snapshot RPC now additively returns a `tombstones` array alongside `items`:
```json
{
  "schema_version": 1,
  "user_id": "...",
  "reset_version": "0",
  "items": [ ... ],
  "tombstones": [
    {
      "item_key": "...",
      "language": "zh",
      "kind": "saved_words",
      "written_form": "你好",
      "reading": "nǐ hǎo",
      "revision": "3",
      "deleted_at": "2026-10-29T13:00:00Z"
    }
  ]
}
```
Existing consumers parsing `snapshot.items` continue to function without changes.

### 5.2. `public.s2s_import_guest`
During guest import, when processing items to merge or import:
- The function now queries `public.user_item_tombstones` for each item.
- If a server tombstone exists for `(user_id, item_key)` with a revision greater than or equal to the candidate item's revision, the item is **skipped**.
- This guarantees that items deleted by the learner on one device are not resurrected by a subsequent guest import.

## 6. Concurrency & Transactional Safety

1. **Row-Level Serialization**:
   All three RPCs (`s2s_apply_mutations`, `s2s_reset_learning`, `s2s_import_guest`) begin by locking the owner's `private.account_state` row via:
   ```sql
   select s.reset_version, s.deleting into generation, deleting
     from private.account_state s where s.user_id = owner for update;
   ```
   This serializes concurrent mutation batches, imports, and resets for the same account, preventing lost updates and race conditions.
2. **Account Deletion Safety**:
   If `deleting = true`, operations halt immediately with `ACCOUNT_UNAVAILABLE (42501)`.
3. **Batch Atomicity**:
   All modifications inside an invocation run within a single PostgreSQL transaction. If validation fails for any mutation item in the batch, the entire batch and its idempotency receipt roll back together.

## 8. Client Integration Guidance (Next Steps)

For the subsequent client implementation:
1. **Sync State Tracking**: Use `account_state.reset_version` returned from snapshots and mutations. If the server returns `RESET_VERSION_CHANGED`, clear local unsynced mutations and fetch a fresh snapshot.
2. **Local Mutation Queue**: Maintain an ordered queue of local changes (`op`, `client_id`, `base_revision`, `item_key`, `data`).
3. **Network Retries**: Retain `request_id` across network retries until a definitive acknowledgement or unrecoverable error is received.
4. **Conflict Resolution**: For `status: "conflict"`, replace local record with server state or present learner conflict resolution if local changes were unsynced.
